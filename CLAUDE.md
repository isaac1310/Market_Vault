Personal project. Hebrew RTL price tracker. See `README.md` for what it is and
how it builds.

## Identity — never use the work account

This repo is personal. Commits are **Itzik Avineta <issacavineta@gmail.com>** on
the **isaac1310** GitHub account. The Locusview address
(`Itzik.avineta@locusview.com`) and the `itzikavineta` GitHub account must never
appear here — beyond being wrong, a non-owner commit author makes Vercel's Hobby
plan refuse the deploy.

Three things enforce this; none needs thinking about day to day:

| Layer | Where | What it does |
|---|---|---|
| Author | `.git/config` + `~/.gitconfig` `includeIf` on the isaac1310 remote | Sets the personal identity automatically, in any folder |
| Credentials | repo-local `credential.helper` in `.git/config` | Pushes with the isaac1310 token **whichever account `gh` is active as** |
| Guard | `.git/hooks/pre-push` | Refuses to push any commit carrying a non-personal email |

`gh` on this machine holds both accounts and flips back to the work one on its
own. That used to cause `403 denied to itzikavineta`; the pinned credential
helper makes it irrelevant. Do not "fix" a push failure by switching the global
`gh` account — it breaks work tooling and is no longer necessary.

Hooks are not committed. If the repo is ever re-cloned, reinstall the pre-push
guard.

## Build and deploy

`price-tracker.html` is the only file edited. `deploy/` and `vault-mart.html` are
generated by `node build.mjs` and git-ignored; Vercel runs the build on push, so
committing a stale copy is impossible.

## Verifying a change

Run the logic suite before claiming anything works: `__selftest()` in the console,
or open with `?dev=1`. All checks must pass — a skip is a failure unless it says
why.

Two traps when checking in a browser, both of which have produced false results:

- The boot animation applies `scaleY(.6)` to `#main`. Any `getBoundingClientRect`
  taken while it runs is wrong — a 44px button measures 26px. Remove the `boot`
  class and wait before measuring.
- The service worker serves a cached page. Unregister it and reload with a
  cache-buster query, or you will verify the previous build.

Write an assertion for any bug that actually shipped. The suite exists to catch
regressions, not to describe things that were never broken.
