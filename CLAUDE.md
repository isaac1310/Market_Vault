Hooks are not committed. If the repo is ever re-cloned, reinstall the pre-push
guard.

## Build and deploy

`price-tracker.html` is the only file edited. `deploy/` and `vault-mart.html` are
generated by `node build.mjs` and git-ignored; Vercel runs the build on push, so
committing a stale copy is impossible.

## Shape of the app (v7)

Home is **השווה** (compare-now), then מוצרים, חנויות, נתונים. The old מחשבון
tab is retired; `#calc` maps to `#compare`. Schema is **6**: a price snapshot
may carry `regularPrice` (only meaningful with `isSale`). The current shop
lives in `priceTracker.shop`, outside `state`, like the theme.

## Verifying a change

Run the logic suite before claiming anything works: `__selftest()` in the console,
or open with `?dev=1`. All checks must pass — a skip is a failure unless it says
why.

Two traps when checking in a browser, both of which have produced false results:

- The boot animation applies `scaleY(.6)` to `#main`. Any `getBoundingClientRect`
  taken while it runs is wrong — a 44px button measures 26px. Remove the `boot`
  class and wait before measuring.
- The service worker serves a cached page. Unregister it and reload with a
  cache-buster query, or you will verify the previous build.
- **The browser pane can report a 0px viewport** when hidden. Every
  `getBoundingClientRect` is then nonsense (a 44px button reads 26–34px).
  Set an explicit size with the resize tool before measuring anything.
- On the local Python `http.server`, the CDP-driven pane sometimes refuses to
  install the service worker ("unknown error fetching the script") even though
  the file serves 200 with the right MIME. Verify the worker on the Vercel
  deploy, not on localhost.

Write an assertion for any bug that actually shipped. The suite exists to catch
regressions, not to describe things that were never broken.
